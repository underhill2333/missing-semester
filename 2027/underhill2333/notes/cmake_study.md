##程序的编译流程

- 程序的编译主线
  hello.c（文本）→ 预处理 .i（文本）→ 编译 .s（汇编文本）→ 汇编 .o（二进制可重定位目标文件）→ 链接 可执行文件（二进制）

- 预处理（产物i）
  按 # 指令把文本改一遍。它不懂 C 语言语法，只在字符层面做替换和粘贴。就是把人话初步翻译为机器语言，AI给了一个合适的比喻，可以把源代码想象成中文写的菜谱——厨师（程序员）看得懂，但厨房里的机器（CPU）不认中文。
  
###名词解释
  宏：纯文本替换。写 #define N 100，之后代码里每个 N 都被换成 100。
  声明：告诉编译器有这么个东西，长什么样
  定义：分配空间，实现储存功能

- 编译（产物s）
  把一个源文件翻译成汇编代码。下面是AI给出的比喻你可以把编译器理解为一个精通中英双语的翻译官，把中文菜谱翻译成英文菜谱，供后面的“炒菜机”阅读。（汇编语言太复杂了我就了解一下就溜了）

###名词解释
  汇编语言：比机器码好读一点点的人类可读版机器指令，一条汇编通常对应一条 CPU 指令。寄存器就是 CPU 手里那几个极快的临时格子。

- 汇编（产物o）
  把汇编代码逐条翻译成机器码，打包成目标文件。此时的汇编语言已经很硬件了。

###名词解释
  机器码 / 指令集：CPU 真正能执行的二进制指令。指令集就是这个 CPU 的「方言表」，x86 和 ARM 说的话不一样——所以同一个程序换架构就得重新编译。
  交叉编译：在 x86 电脑上编译出 ARM 板子能跑的程序。做嵌入式时才需要。

- 链接
  机器码已经搞好了（o文件），然后把o文件拼成一个可执行文件。拼接零件和接上外部库。

###名词解释
  库：就是别人提前*编译*好的一堆代码或者函数，然后打包给你用。比如C语言中的prinf，prinf的实现不是你来写，就是人家已经写好在标准库里。其实就是造好的工具
  静态库：链接时，链接器会从静态库里只挑出你用到的那些目标模块，复制进最终可执行文件。不是整个库无脑塞进去，但用到的部分会被“焊死”进程序。
  共享库：共享库不是复制进你的可执行文件，而是：可执行文件里只记录“我需要某个库里的某个函数”，运行时由系统把共享库加载进内存，大家共用。
